# 02. Apache /Kafka Connector

## 02-1. Kafka Connect 개요(요약)

Kafka Connect는 Apache Kafka와 다른 System 간에(Source and Sink) 확장 가능하고 안정적인 Data Streaming을 위한 Tool이다.

Kafka Connect는 독립 실행형(Standalone)과 분산 실행형(Distributed) 두 가지 중 하나를 선택해서 사용할 수 있다.

bin/connect-standalone.sh 또는 /bin/connect-distributed.sh CLI 툴을 사용해서 정의할 수 있다.

> 독립형 모드에서는 두 개의 매개변수를 전달할 수 있다.<br> > **첫번째 매개변수**는 Worker의 설정을 정의하며 **두번째 매개변수**는 Connector를 설정한다. 분산형 모드는 Worker 설정을 정의할 수 있지만 Connector를 설정하려면 REST API를 사용해야한다.(독립형 모드도 REST API를 사용할 수 있음)
>
> > Debezium/connect 이미지에서는 기본적으로 분산형 모드를 사용하는듯함. Group_id가 필수(required)라고 되어있음

## 02-2. Transformations

Kafka Connect 문서에는 **Transformations** 문단이 존재한다. 이건... 잘 모르겠다. 대충 내용을 훑어보면 Message 또는 File의 내용을 특정한 형식으로 변환시키는 용도로 사용하는듯하다. Connector를 연결해본다음 예제를 수행하는 형식으로 테스트해보자(Kafka 문서에서는 독립형 모드로 테스트하는 예제가 존재한다.)

## 02-3. REST API

> 해당 문서에서는 REST API End-points List가 제공된다. 하지만, Connector 설정과 관련된 Properties값들은 제공되지 않는다. Properties 관련 내용은 **Debezium Connector for Mariadb** 문서를 참조해야함

Kafka Connect는 Service로 실행되도록 설계되었으므로 Connector 관리를 위한 REST API가 제공된다.

기본적으로 listener를 지정하지 않으면 HTTP protocol을 사용하여 8083 포트에서 실행된다.

end-points 목록은 공식 문서 참조

# 03. Debezium MariaDB Connector

## 03-1. How the connector works

-   **initial snapshot**

처음 Connector를 실행했을 때 한번 실행하는 스냅샷임.<br>
전체 MariaDB Table Schema 구조를 Schema history topic에 저장하는 역할을 함<br>

"snapshot.mode" 속성값과 관련있음<br>
본문에서의 설명은 더 복잡하고 어려우나... 이해못하겠다.(일단대기)<br>

-   **ad hoc snapshot(임시 스냅샷)**

1. 무엇인가???

    - initial snapshot 이후 실행 도중 추가로 스냅샷 찍을 때 사용됨

2. 언제 사용되는가??

    - 새로운 Table이 캡쳐 대상으로 추가되었을 때
    - Table이 일시적으로 제외되었다가 다시 캡쳐 대상으로 포함될 때 Debezium은 자동으로 이를사용함
    - Signaling Table 또는 Signaling Topic에 "execute-snapshot" 명령/항목?을 넣으면 실행함

3. 무슨 역할을 하는가?

    - 대충 기존에 있던 스냅샷을 업데이트하는데 사용함

4. 기타 등등
    - Signaling tables 라던가 Signaling topic, Signal 등등 다양한 용어들이 등장함
    - execute-snapshot 메시지를 전송하여 캡쳐할 Table 및 Signal Type을 증분 또는 차단으로 설정할 수 있다.
    - 증분 스냅샷(Incremental Snapshot)과 차단 스냅샷(Blocking Sanpshot)과 관련됨

-   **incremental snapshot(증분 스냅샷)**

무중단 방식

-   **blocking snapshot**

initial snapshot과 유사함
